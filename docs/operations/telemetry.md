# Telemetry Integration (TEL-04)

## Overview

The hugo-translator project has been integrated with the TEL-03 telemetry platform to track translation metrics, token usage, cache performance, and file operations.

## Features Implemented

### 1. Token Tracking

- **Input Tokens**: Tokens sent to the translation model
- **Output Tokens**: Tokens generated by the model
- **Cached Tokens**: Estimated tokens saved via Translation Memory hits
- **Total Tokens**: Total tokens processed (cached + translated)

### 2. File Operation Tracking

- **Files Added**: New `.md` files created
- **Files Updated**: Existing `.md` files overwritten
- **Bytes Written**: Total bytes written to `.md` files
- **TM Entries**: Translation Memory entries stored

### 3. Cache Performance Metrics

- **TM Hit Rate**: Percentage of segments found in cache
- **Token Cache Rate**: Percentage of tokens served from cache
- **Layer Breakdown**: L1 (in-memory), L2 (persistent), L3 (semantic) hit counts

### 4. Session Tracking

- Each translation operation gets a unique `run_id`
- Batch operations aggregate metrics across all files
- Full context preserved (source files, target languages, etc.)

## Configuration

### Enable/Disable Telemetry

Telemetry is **enabled by default**. To disable it:

**Option 1: Environment Variable**
```bash
export HUGO_TRANSLATOR_TELEMETRY_ENABLED=false
```

**Option 2: Code Configuration**
```python
from translation_engine import TranslationEngine

engine = TranslationEngine(
    config_service=config,
    tm=tm,
    model_loader=loader,
    enable_telemetry=False  # Disable telemetry
)
```

### Configure Telemetry Settings (HTTP API + Buffer)

The telemetry client uses an HTTP API architecture with local buffering for guaranteed delivery:

```bash
# Telemetry API endpoint (default: http://localhost:8765)
# Note: local-telemetry uses METRICS_API_URL environment variable
export METRICS_API_URL=http://localhost:8765

# Local buffer directory (default: ./telemetry_buffer)
# Events are buffered locally and synced when API is available
export TELEMETRY_BUFFER_DIR=C:/telemetry/hugo-translator/buffer

# Path to telemetry module source (if non-standard location)
export TELEMETRY_SRC_PATH=C:/path/to/local-telemetry/src

# Agent owner identifier
export AGENT_OWNER=your-username
```

**Architecture Benefits:**
- **No database corruption**: Client never writes directly to database
- **Guaranteed delivery**: Events buffered locally if API unavailable
- **Zero data loss**: Buffer files retained until successfully synced
- **Concurrent-safe**: No "database is locked" errors

## Usage

### Automatic Tracking

Telemetry tracking happens **automatically** when you use the TranslationEngine:

```python
from translation_engine import TranslationEngine

# Initialize engine (telemetry enabled by default)
engine = TranslationEngine(config, tm, loader)

# Translate a file - telemetry tracked automatically
result = engine.translate_file(
    site_id="my-site",
    file_path=Path("content/example.md"),
    target_langs=["es", "fr"]
)

# Check the stats
print(f"Tokens input: {result.stats.tokens_input}")
print(f"Tokens cached: {result.stats.tokens_cached}")
print(f"Cache hit rate: {result.stats.tm_hit_rate:.1%}")
print(f"Files added: {result.stats.md_files_added}")
```

### Batch Translation

```python
# Translate entire directory - aggregated telemetry
result = engine.translate_directory(
    site_id="my-site",
    directory=Path("content/"),
    target_langs=["es", "fr"],
    recursive=True,
    parallel=True
)

# Get aggregated stats
agg_stats = result.aggregate_stats
print(f"Total tokens processed: {agg_stats.tokens_total}")
print(f"Total files: {result.total_files}")
print(f"Successful: {result.successful_files}")
```

## Telemetry Data Storage

Telemetry data flows through the following architecture:

1. **Local Buffer Files**: `{TELEMETRY_BUFFER_DIR}/*.jsonl`
   - Client writes events to local .jsonl buffer files
   - Files transition through states: `.active` → `.ready` → `.synced`
   - Zero data loss even if API is down

2. **HTTP API Service**: `{TELEMETRY_API_URL}/api/v1/events`
   - Client POSTs events to telemetry API service
   - API service handles database writes (server-side)
   - Concurrent-safe, no client-side locking

3. **Central Database**: (Server-side, managed by API service)
   - SQLite database managed by telemetry API service
   - Tables: `agent_runs`, `agent_events`
   - Clients query via API endpoints, not direct DB access

## Viewing Telemetry Data

### Query via HTTP API

```bash
# Get recent translation runs
curl http://localhost:8765/api/v1/runs?agent_name=hugo-translator&limit=10 | jq .

# Get specific run details
curl http://localhost:8765/api/v1/runs/{run_id} | jq .

# Check API health
curl http://localhost:8765/health
```

### Inspect Local Buffer Files

```bash
# View buffered events awaiting sync
ls C:/telemetry/hugo-translator/buffer/*.jsonl.ready

# Inspect buffer file contents
cat C:/telemetry/hugo-translator/buffer/telemetry_20251220.jsonl.active | jq .
```

### Python API Client

```python
import requests

# Query recent runs
response = requests.get(
    "http://localhost:8765/api/v1/runs",
    params={"agent_name": "hugo-translator", "limit": 10}
)
runs = response.json()

for run in runs:
    print(f"{run['job_type']}: {run.get('items_succeeded', 0)} items")
```

## Metrics Tracked

| Metric | Type | Description |
|--------|------|-------------|
| `tokens_input` | int | Input tokens to model |
| `tokens_output` | int | Output tokens from model |
| `tokens_cached` | int | Tokens from cache (estimated) |
| `tokens_total` | int | Total tokens processed |
| `total_segments` | int | Total translation segments |
| `tm_hits` | int | Translation Memory hits |
| `l1_hits` | int | L1 cache hits (in-memory) |
| `l2_hits` | int | L2 cache hits (persistent) |
| `l3_hits` | int | L3 cache hits (semantic) |
| `translated_segments` | int | New translations via model |
| `md_files_added` | int | New `.md` files created |
| `md_files_updated` | int | Existing `.md` files updated |
| `bytes_written_md` | int | Bytes written to `.md` files |
| `tm_entries_stored` | int | TM entries stored |
| `tm_hit_rate` | float | TM hit rate (0-1) |
| `token_cache_rate` | float | Token cache rate (0-1) |
| `duration_seconds` | float | Operation duration |

## Architecture Changes

### Modified Files

1. **`src/translation_engine/models.py`**
   - Extended `TranslationStats` with token and file operation metrics

2. **`src/model_runtime/loader.py`**
   - Added `translate_with_token_counts()` to `HuggingFaceBackend`
   - Token counting using `.numel()` on input/output tensors

3. **`src/translation_engine/engine.py`**
   - Added `estimate_token_count()` helper function
   - Token tracking in `_translate_to_language()`
   - File operation tracking (add vs. update)
   - TM entry storage tracking
   - Telemetry hooks in `translate_file()` and `translate_directory()`

4. **`src/observability/telemetry_integration.py`** (NEW)
   - `TranslationTelemetry` class for integration
   - Context managers for tracking sessions
   - Graceful degradation if telemetry unavailable

### Backward Compatibility

- **100% backward compatible**: All changes are additive
- Telemetry can be disabled without affecting functionality
- Existing code continues to work unchanged
- New metrics are optional and don't break APIs

## Troubleshooting

### Telemetry Not Working

1. **Check if telemetry is enabled**:
   ```python
   print(engine.telemetry.is_available())
   ```

2. **Check environment variables**:
   ```bash
   echo $HUGO_TRANSLATOR_TELEMETRY_ENABLED
   echo $METRICS_API_URL
   echo $TELEMETRY_BUFFER_DIR
   ```

3. **Verify API is running**:
   ```bash
   curl http://localhost:8765/health
   # Expected: {"status": "ok", "version": "..."}
   ```

4. **Check buffer directory**:
   ```bash
   ls $TELEMETRY_BUFFER_DIR
   # If API is down, you'll see .jsonl.ready files accumulating
   ```

5. **Check logs for errors**:
   - Telemetry errors are logged as warnings and don't break translation

### API Connection Issues

**Symptom**: Events not appearing in telemetry database

**Cause**: Telemetry API not running or unreachable

**Impact**: Events buffered locally (no data loss)

**Fix**:
```bash
# Start telemetry API service
# Events will sync automatically when API comes online
```

**Workaround**: Events are safe in buffer directory, will sync when API is restored

### Buffer Directory Filling Up

**Symptom**: Many `.jsonl.ready` files in buffer directory

**Cause**: API down for extended period

**Impact**: Disk space usage increases

**Fix**: Start API; buffer sync worker will process backlog

**Prevention**: Monitor buffer directory size and API uptime

### Telemetry Overhead

- **Minimal overhead**: ~1-2% performance impact
- Token counting uses existing tensors (no extra computation)
- File tracking uses simple checks before writes
- Buffer writes are fast (local filesystem, no network if API down)
- Non-blocking: Translation continues even if telemetry fails

### Disabling Telemetry

If telemetry causes any issues, disable it:

```bash
export HUGO_TRANSLATOR_TELEMETRY_ENABLED=false
```

Or in code:

```python
engine = TranslationEngine(
    config, tm, loader,
    enable_telemetry=False
)
```

## Upgrading

### Architecture Versions

| Version | Architecture | Status | Recommended |
|---------|--------------|--------|-------------|
| **2.0** | HTTP API + Buffer | ✅ **Current** | ✅ **Yes** |
| 1.0 | Direct SQLite | ⚠️ Deprecated | ❌ No (corruption risk) |

### Migration Guide

If you're upgrading from version 1.0 (direct SQLite) to version 2.0 (HTTP API + buffer), see:

📘 **[Telemetry Migration Guide](TELEMETRY_MIGRATION_GUIDE.md)** - Complete migration instructions

**Quick Summary**:
- **Good news**: Latest hugo-translator already uses HTTP API architecture
- **What you need**: Configure `METRICS_API_URL` and `TELEMETRY_BUFFER_DIR` in `.env`
- **Migration time**: 10-15 minutes (mostly verification)
- **Data loss**: None (existing data preserved)

### Rollback Guide

In case you need to rollback (not recommended):

⚠️ **[Telemetry Rollback Guide](TELEMETRY_ROLLBACK_GUIDE.md)** - Emergency rollback procedures

**Note**: Rollback is **not recommended** due to corruption risk in old architecture. Consider disabling telemetry instead (`TELEMETRY_ENABLED=false`).
