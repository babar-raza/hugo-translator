# Data Retention Policy

**Last Updated:** 2026-06-10
**Applies to:** Hugo Translation System production deployments

## Overview

This document defines retention periods and cleanup procedures for data generated by the translation system. All retention periods are measured from creation date.

## Retention Schedule

| Data Type | Location | Retention | Cleanup Method |
|-----------|----------|-----------|----------------|
| **Agent metrics evidence** | `data/metrics/agent_evidence/` | 90 days | Delete directories older than 90 days |
| **Metrics ledger** | `data/metrics/agent_evidence/metrics_ledger.jsonl` | 90 days | Rotate: archive and truncate |
| **Run history database** | `data/metrics/run_history.db` | 365 days | DELETE WHERE timestamp < (now - 365d) |
| **Benchmark database** | `data/benchmarks/benchmark.db` | Indefinite | Compact quarterly: VACUUM |
| **Translation Memory (L2)** | `data/tm/l2_translations.mdb` | Indefinite | Configured max_size_mb (default 1536MB) with LRU eviction |
| **TM improvement queue** | `data/tm/improvement_queue.jsonl` | Until processed | Consumed by TM improvement worker |
| **TM seen hashes** | `data/tm/improvement_queue_seen.json` | Indefinite | Auto-rotated at 50K entries (TC-07) |
| **Worker state files** | `data/logs/*.state.json` | 30 days | Delete files older than 30 days |
| **Worker heartbeat files** | `data/logs/*.heartbeat` | 7 days | Delete files older than 7 days |
| **Log files** | `data/logs/*.log` | 30 days | Rotate: logrotate or manual deletion |
| **Run metrics** | `data/metrics/run_metrics/` | 90 days | Delete files older than 90 days |
| **Scope audit** | `data/metrics/scope_audit.json` | Overwritten each run | No cleanup needed |
| **Content metadata** | `.translation_metadata.json` (per content root) | Indefinite | Auto-cleaned by CHH-05 (stale entry removal) |

## Cleanup Commands

### Evidence sidecars (90-day retention)

```bash
# Linux/macOS
find data/metrics/agent_evidence/ -type d -mtime +90 -exec rm -rf {} +

# Windows (PowerShell)
Get-ChildItem -Path data\metrics\agent_evidence -Directory |
  Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-90) } |
  Remove-Item -Recurse -Force
```

### Worker state and heartbeat files (30/7-day retention)

```bash
# Linux/macOS
find data/logs/ -name "*.state.json" -mtime +30 -delete
find data/logs/ -name "*.heartbeat" -mtime +7 -delete

# Windows (PowerShell)
Get-ChildItem -Path data\logs -Filter *.state.json |
  Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-30) } |
  Remove-Item -Force
Get-ChildItem -Path data\logs -Filter *.heartbeat |
  Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-7) } |
  Remove-Item -Force
```

### Run history database (365-day retention)

```bash
python -c "
import sqlite3
from datetime import datetime, timedelta
cutoff = (datetime.utcnow() - timedelta(days=365)).isoformat()
conn = sqlite3.connect('data/metrics/run_history.db')
conn.execute('DELETE FROM run_outcomes WHERE timestamp < ?', (cutoff,))
conn.execute('VACUUM')
conn.commit()
conn.close()
print('Cleanup complete')
"
```

### Benchmark database (quarterly compaction)

```bash
python -c "
import sqlite3
conn = sqlite3.connect('data/benchmarks/benchmark.db')
conn.execute('VACUUM')
conn.commit()
conn.close()
print('Compaction complete')
"
```

## Automation

For automated cleanup, add cleanup commands to the system's Task Scheduler (Windows) or crontab (Linux):

```
# Example crontab entry: run cleanup weekly on Sunday at 3 AM
0 3 * * 0 /path/to/scripts/cleanup_retention.sh >> /var/log/retention_cleanup.log 2>&1
```

## PII and Sensitive Data

- **No PII is stored** in metrics, evidence, or TM data. Source content is technical documentation.
- **Agent metrics token** is stored in environment variables only (never in config files or databases).
- **System paths** in benchmark data are sanitized (OneDrive paths, user home dirs replaced with placeholders).

## Compliance Notes

- Retention periods align with the SLA reporting cadence (monthly/quarterly) defined in [sla.md](../operations/sla.md).
- Evidence sidecars are the audit trail for metrics posting — 90 days covers 3 monthly SLA review cycles.
- All data is local-only (no cloud storage, no third-party data processors) except metrics posted to the agent metrics API.
