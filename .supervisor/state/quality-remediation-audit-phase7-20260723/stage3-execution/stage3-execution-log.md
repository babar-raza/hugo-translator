## Verification methodology actually used (not just planned)

- Every fixer's canary/batch output checked against real production files, not just script exit codes.
- Two production incidents (table-cell corruption, both original and recovery-script) were found via **direct `git diff` inspection of specific files**, not via the fixers' own self-reported success counts -- confirms `verify_fix.py`'s automated checks, while valuable, are not a substitute for spot-checking real diffs on the highest-risk categories.
- Corruption-signature sweep (checking all 434 table_desc_not_translated candidates for the literal header-word-as-content signature, correctly excluding header rows themselves) run twice: after the fix, and after final restore -- both times 0 hits.
- Unit test suites for every fixer updated with regression tests reproducing the exact real-world bug found (not generic coverage) -- e.g. `test_process_file_aligns_by_row_key_not_line_position`, `test_process_file_treats_duplicate_en_key_as_ambiguous_not_a_guess`, `test_link_targets_resolve_accounts_for_hugo_leaf_page_url_segment`, `test_fix_file_aligns_by_heading_level_not_exact_translated_text`.
