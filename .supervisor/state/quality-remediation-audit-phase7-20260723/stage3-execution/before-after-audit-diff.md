## Investigation: docs.aspose.org double_period spike (121 -> 1,348)

The aggregate double_period delta is dominated by one site: `docs.aspose.org` alone jumped from 121 to 1,348 (+1,227); `kb.aspose.org` (-51) and `reference.aspose.org` (-205) both dropped as expected from TC-P7-04's fixes. This spike was investigated directly against the actual file content on disk, not accepted from the audit tool's own count:

1. Sampled 1,348 flagged `docs.aspose.org` files' raw text, stripped code fences, and separately stripped markdown link targets (`](...)`) before re-testing for a stray `..`.
2. **1,347 / 1,348 (99.93%)** have zero stray `..` once link targets are excluded — every one of these is a file where TC-P7-05 correctly restored a `../` link, and the audit tool's own `double_period` detector re-flags it because — like Gate 12 before this mission's fixes — **it has the identical unprotected-regex flaw**: it excludes code fences but not markdown link targets. This is a pre-existing gap in `audit_all_content.py`'s own detector, exposed (not caused) by this mission's fixes, and is documented as a follow-up (see final report).
3. **1 / 1,348** is a genuine stray double-period, in `content/docs.aspose.org/ro/cells/cpp/getting-started/license.md`, frontmatter `description:` field: `"...proiectul dvs.."` — a Romanian sentence ending in the abbreviation "dvs." immediately followed by the sentence's closing period. Its frontmatter `provenance.last_mechanism: skill` shows it was generated by the **concurrent content-repo pipeline's own skill mechanism**, not by this mission (this mission's fixers only ever modify a file's *existing* body/frontmatter values, never generate new prose) — confirmed out of scope, not a regression this mission introduced.

**Conclusion**: the double_period category's true post-fix state (once the audit tool's own link-target blind spot is accounted for) is a net improvement, consistent with every other category — not a regression.
