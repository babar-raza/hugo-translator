### TASK-2.5 & 2.6: Verifier Improvement Proposals

While verifier robustness improvements would help future-proof the system, the **primary issue is translation pipeline configuration**, not verifier failure.

**Proposed improvements** (see `workstream2_proposed_improvements.txt`):

1. **Pre-flight checks**:
   - Target file exists
   - Target file readable
   - Valid UTF-8 encoding
   - Not empty
   - Valid Markdown structure

2. **Exception handling**:
   - Wrap all verifier logic in try-except
   - Always produce valid JSON output
   - Include error type, message, traceback
   - No silent failures

3. **Structured error responses**:
   ```json
   {
     "passed": false,
     "error": "FILE_NOT_FOUND",
     "error_message": "Target file not found: /path/to/file.md",
     "error_type": "FileNotFoundError",
     "traceback": "...",
     "source": "/path/to/source.md",
     "target": "/path/to/target.md",
     "lang": "fr",
     "checks": {}
   }
   ```

**Expected Impact**: If implemented, 0 "no verification data" cases in future runs (all failures will have structured error info).

### Root Cause Summary

**Category**: Translation Pipeline Configuration Error
**Severity**: High (prevented 48 files from being translated)
**Location**: Translation CLI invocation (batch mode vs single file mode)

**What Happened**:
1. Phase 6 process created batch filelist files (batch_7_filelist.txt, batch_8_filelist.txt, etc.)
2. Translation CLI was invoked with these filelist files as INPUT
3. CLI processed filelists themselves as markdown content
4. CLI did NOT read filelists and translate files listed within
5. Target files were never created
6. Verifier had nothing to verify → "No verification data"

**What Should Have Happened**:
1. CLI should have parsed filelist files
2. For each path in filelist, translate that file
3. Create target files in appropriate locations
4. Verifier verifies each translated file

**Fix Required**:
- Review translation CLI invocation in Phase 6 driver script
- Ensure correct input mode flag (e.g., `--filelist` vs `--input`)
- Verify CLI correctly processes batch filelist files
- Re-run translation for affected 48 files with correct CLI mode

### TASK-3.3: Linguistic Research Context

**Translation Industry Standards** (English → French):

1. **Expected Expansion**: French text is typically **15-20% LONGER** than English
   - Technical documentation: 10-15% expansion
   - Expected ratio: 1.10 to 1.20 (110-120%)

2. **Actual Data**: Mean ratio of **97.94%** indicates text got SHORTER
   - This is **unusual** for EN→FR translation
   - Possible causes:
     - Aggressive line wrapping in target (Markdown formatting)
     - List structure changes (collapsed nested lists)
     - Content omission (quality issue)

3. **Threshold Context**:
   - Industry standard would expect ratio ≥100%
   - A 95% threshold (allowing 5% shrinkage) is already **lenient for French**
   - A 90% threshold would allow 10% shrinkage (very lenient)

4. **Line Count Limitations**:
   - Line breaks are Markdown formatting artifacts, not semantic content
   - Same content can have different line counts based on:
     - Line wrap preferences
     - List item formatting
     - Paragraph breaks
   - **Word count** or **token count** would be more reliable metrics

### TASK-3.4: Threshold Recommendation

**RECOMMENDATION: KEEP 95% THRESHOLD**

**Justification**:

1. **Data-Driven**:
   - Mean ratio (97.94%) indicates most translations meet or exceed 95%
   - All 33 passing files have ratio ≥95%
   - Clear separation between passing and failing files

2. **Linguistic Validity**:
   - French typically expands 10-20%, not shrinks 5%+
   - Files failing threshold likely have genuine quality issues:
     - Missing translations
     - Truncated content
     - Overly aggressive summarization

3. **False Positive Analysis**:
   - 0 passing files in 90-95% range
   - Relaxing to 90% would not recover legitimate translations
   - Would only allow lower-quality translations to pass

4. **Risk Assessment**:
   - **LOW RISK**: False positives minimal based on mean ratio
   - Keeping strict threshold protects against incomplete translations
   - 54 line count failures (19.8% of 248) likely represent genuine issues

**Alternative Consideration**:

While the 95% threshold is appropriate, **line count may not be the optimal metric** for Markdown translation quality. Consider future enhancement:

- **Token count ratio**: More semantic than line breaks
- **Word count ratio**: Language-agnostic comparison
- **Character count ratio**: Accounts for text density

These metrics would be less sensitive to Markdown formatting variations while still detecting content omission.
