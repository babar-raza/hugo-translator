    fix(orchestrator): resolve 6 root causes behind silent no-work cycles
    
    RC-1: Anchor CWD to project root in main() so all relative file paths
    (queues, state, PID files) resolve correctly regardless of launch directory.
    This was the primary cause: all trigger evaluations returned False because
    Path("data/retranslate_queue.jsonl").exists() resolved against wrong CWD.
    
    RC-2: Elevate per-worker skip reasons from logger.debug to logger.info and
    replace misleading "all triggers inactive" with "No workers launched this
    cycle" — the previous message was wrong when blocks were PID/cooldown, not
    trigger evaluation failures.
    
    RC-3: Auto-cleanup stale PID files in should_launch(). Previously, a dead
    worker's PID file blocked re-launch forever. Now: if the PID file exists but
    the process is dead, delete it and log at INFO before proceeding. Also adds
    cfg.get("pid_file_name", name) to read the correct PID filename per worker.
    
    RC-4: Add pid_file_name: tm_worker to config/workers.yaml for
    tm_improvement_worker. The worker uses _worker_id = "tm_worker" (canonical
    per AGENTS.md) so it writes tm_worker.pid; the orchestrator was checking
    tm_improvement_worker.pid — a file that never existed.
    
    RC-5: Warn (once) when a file_change trigger path contains an unresolved
    ${ENV_VAR} placeholder. Previously silent; now logs WARNING with dedup via
    module-level _warned_unresolved_paths set.
    
    RC-6: Rename state field recently_completed_workers → recently_launched_workers.
    Workers are launched asynchronously via Popen; the field stores workers just
    launched this cycle, not workers that have completed. Name now matches reality.
    
    Tests: 287 passed, 0 failed. Updated test_orchestrator_triggers.py to match
    renamed field and to use monkeypatch.chdir for the PID file path test.
    
    Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>
